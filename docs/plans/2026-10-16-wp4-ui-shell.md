# WP4 UI Shell and Timeline Implementation Plan

> **For Claude:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task.

**Goal:** Build the translated browser editor shell and a responsive, navigable timeline backed by the WP3 API.

**Architecture:** Keep browser state in a small store, keep frame/time and coordinate math in pure modules, and isolate DOM, canvas, and API effects in view modules. Use the existing locale catalog and endpoint for every visible message, and let the server remain the source of project and transport state.

**Tech Stack:** Plain ES modules, Canvas 2D, browser APIs, Node's built-in test runner, Biome.

**Progress (2026-10-16):** Tasks 1–4 have an initial implementation. The pure timeline tests pass. Task 5 and the required integration, lint, and browser acceptance checks remain in progress.

---

### Task 1: Pure timeline math and tests

Add `format.js` and `store.js` pure helpers and `ui/tests/timeline.test.js`. Test frame formatting, zoom conversion, anchor-preserving zoom, lane hit testing, and clip hit testing; run the new tests and observe failure before implementing.

### Task 2: API client and UI state

Add `api.js` for state, edit, command, transport, peaks, and live WebSocket calls. Add `store.js` state initialization and immutable updates for project, selection, playhead, view, focus, and playback. Cover pure store behavior with node tests.

### Task 3: Canvas timeline

Add `timeline.js` with adaptive ruler, lanes, clips, waveform cache, selection, playhead, and pointer hit testing. Test pure coordinate/waveform math. Draw only after state changes or live playback updates.

### Task 4: Shell and controls

Add `index.html`, `style.css`, `app.js`, `tracks.js`, and `inspector.js`. Include translated transport, project title, track and bus controls, timeline, inspector, focus areas, and responsive no-page-scroll layout. Ensure every visible string has English and Finnish catalog entries.

### Task 5: Navigation and acceptance

Implement zoom levels and anchors, overview navigation, scrolling, lane/waveform height controls, playhead following, and keyboard focus cycling per WP4. Run UI tests and Biome; run the full Python test and Ruff checks; manually open a two-file project and confirm playback and waveform rendering.

### Task 6: Handoff records

Update the WP4 status, roadmap state, README, and user-facing changelog only when the implementation and acceptance checks are complete. Commit locally; do not push.
