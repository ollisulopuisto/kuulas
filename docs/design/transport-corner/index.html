Design notes

Recommendation

  • C for the comfortable density, B for compact. C keeps Play the biggest target in the window (60 × 56 px) and the timecode at 28 px, readable from the back of the chair, and it says plainly that Silmukka and the speed slider are secondary. B is what C becomes in compact density: 48 px tall, so the lanes start almost where they start today.
  • A works too, but it spends 80 px of height and puts Play, Silmukka and the speed chip in one row of three equal buttons, so Play no longer stands out by size, only by colour.
  • Height: the corner is overview + ruler. To make room, the overview strip grows: C 72 px (overview 48), A 80 px (overview 56), B 48 px (overview 24); today it is 44 (overview 20). A taller overview is more useful anyway (12 px per track for four tracks). The top bar stays 52 px.
  • Width: the header column goes from 272 to 340 px (232 to 280 below 1400 px). The timeline loses 68 px; the menus get about 400 px.
  • The menu row's left block becomes just the logo and the name (about 110 px). It no longer needs to be as wide as the header column: the corner now does the job of "the eye runs straight down from Play to the playhead". Then all 11 menus fit from about 1280 px up; at 1100 px eight show and Juonto, Näytä and Ohje go into "…". With Kumoa and Tee uudelleen as icon buttons (tooltips "Kumoa · ⌘Z", as section 3.1 already specifies) ten show at 1100 px and only Ohje goes into "…" (F1 still opens help). Recommended too.
  • Speed chip: in C it shows only while fast listening is on (or a shuttle speed plays), as today; its space stays reserved so the corner does not jump. A and B show it at rest as a quiet chip "1,50×": one click turns fast listening on. That adds one resting control (the budget in section 16 is 25); take it only if the owner wants a mouse path to fast listening other than dragging the slider.

Accessibility

  • Focus order follows the DOM: menu row (menus, Kumoa, Tee uudelleen, Tuo ääntä, Vie) → corner (Toista, Silmukka, nopeus slider, speed chip) → track headers → timeline → transcript → sidebar → status bar. The timecode is an <output> and not focusable.
  • The corner is a role="toolbar" group named "Toisto" (ui.toolbar.label today names the top bar; the corner needs its own key, e.g. ui.transport.label). The menu row keeps role="menubar" semantics.
  • Names: Toista keeps its visible label in A and C. Where it is an icon (B, narrow), #play-label stays in the DOM as visually hidden text, so the accessible name still switches Toista / Pysäytä. Silmukka is aria-pressed; the speed slider keeps aria-label "Nopean kuuntelun nopeus (1×–2×, sävelkorkeus säilyy)" and aria-valuetext "1,35×"; the chip gets aria-label from ui.speed.fast_chip_title (its text "1,35×" alone says too little).
  • Keys stay on the controls: aria-keyshortcuts Space (Toista), Meta+U / Control+U (Silmukka), "." (fast listening). The key label under Toista ("Välilyönti" in Finnish, 70 px) appears on hover and keyboard focus and hangs over the first track header, as it does over the ruler today.
  • Hit targets: every corner control is at least 28 × 28 px: Toista 32 px tall (C: 60 × 56), Silmukka 32 (C: 28), icon buttons 32 × 32 (28 × 28 in C's small row), the chip 28 px tall, the slider's input box 28 px tall. The top bar keeps its 40 px buttons with 44 px targets.
  • Not colour alone: loop on = pressed look + bold label + the in/out band in the ruler; fast on = amber chip with the number + the slider at full opacity.
  • The timecode is not aria-live (it would talk all through playback); the playhead time is read on demand from the focused timeline, as today.

What moves in the DOM (ids kept, so the wiring follows)

From header.toolbar into aside.heads, replacing .heads-spacer:

  <div class="corner transport" role="toolbar" data-i18n-aria-label="ui.transport.label">
    <button id="play" type="button" class="play" aria-keyshortcuts="Space">
      <span id="play-icon" class="play-icon" aria-hidden="true">▶</span><span id="play-label" class="lbl"></span>
      <kbd data-shortcut="Space" aria-hidden="true"></kbd>
    </button>
    <output id="timecode" class="timecode" data-i18n-aria-label="ui.transport.time">0:00.000</output>
    <div class="t-row secondary">
      <button id="loop" type="button" class="btn sm" aria-pressed="false" aria-keyshortcuts="Meta+U Control+U">…</button>
      <input id="fast-speed" class="fast-speed" type="range" …>
      <button id="speed-chip" type="button" class="chip warn" hidden></button>
    </div>
  </div>
  <div id="track-headers" class="heads-scroll" …></div>
</aside>
  • Moved, ids unchanged: #play, #play-icon, #play-label, #loop, #timecode, #fast-speed, #speed-chip. app.js looks them up by id, so it needs no change; .toolbar .play rules in style.css become .corner .play.
  • Stay in the menu row: #menubar, #live-chip, #waveform-gain, #group-chip (the .modes div without the speed chip and slider), #undo, #redo, #import, #export, #file-input.
  • #speed-chip: when hidden, keep its box (visibility: hidden instead of hidden) so the corner does not jump; or reserve the width in CSS.
  • Tokens: --heads-w 340, --heads-w-min 280; a new --corner-h (72 comfortable, 48 compact) with --overview-h: calc(var(--corner-h) - var(--ruler-h)). Check that overview.js spreads its rows over the taller strip.
  • .project loses width: var(--heads-w) (and the 1400 px rule that sets it to --heads-w-min).
  • Not yet decided: where the project name and the open edit ("Pääleikkaus · 58:41", WP21) go once they exist. Suggestion: in the logo block, cut with an ellipsis at 200 px; at 1100 px that costs one more menu.
